3. 若沒有 GitHub 寫入工具，必須明確說明「目前這個聊天沒有 GitHub 寫入權限」，不得誤稱專案無法修改。

5. 不得自行合併至 `main`，除非使用者明確要求。

## 資金流入／流出固定交付規格

使用者要的不是摘要，而是每天固定兩份完整檔案：

- `YYYY-MM-DD 台股資金流入.txt`
- `YYYY-MM-DD 台股資金流出.txt`

每份必須完整包含：

- 大盤摘要
- 外資買超／賣超前十完整排行
- 投信買超／賣超前十完整排行
- 五張綠卡
- 五張紅卡
- 代表股
- 籌碼
- 反人性
- 評分
- 操作建議
- 族群現象
- 解讀
- 延續觀察

固定原則：

- 同一交易日資料必須同日交付。
- 官方資料未完整取得時，不得拿其他交易日數字冒充。
- 不得只交法人總額摘要。
- 不得把 HTTP 400 誤判為「沒有資料」。
- 若排行榜介面故障，必須改走上市／上櫃分流抓取後合併排序。
- 上市個股法人資料優先 TWSE。
- 上櫃個股法人資料優先 TPEx。
- 必須保留 requested_date 與 resolved_date；若日期回退，要明確說明。

## 驗收標準

1. 上市、上櫃皆能取得資料。
2. 可輸出外資與投信買超／賣超前十。
3. requested_date 與 resolved_date 正確。
4. 非交易日可回退最近交易日。
5. HTTP 400、格式錯誤與真正查無資料分開處理。
6. 不混入錯誤日期資料。
7. 兩份 TXT 格式完整且可重複產生。
