# 台股資金流入／流出／融資融券固定輸出規格

本檔是鑽石引擎與台股 GPT 的最高優先級輸出契約。

## 零、固定觸發方式

當使用者輸入「日期＋台股」，例如：

- `8/5 台股`
- `8月5日 台股`
- `2026-08-05 台股`

代表一次要求以下三份獨立 TXT：

1. `YYYY-MM-DD 台股資金流入.txt`
2. `YYYY-MM-DD 台股資金流出.txt`
3. `YYYY-MM-DD 台股融資融券觀察.txt`

這不是簡短摘要，也不是一般盤後分析文章。

## 一、分階段交付時序

### 第一階段：法人資金流向

通常約台北時間 18:00 後，當 TWSE 與 TPEx 同日個股法人資料完整時，立即先交付：

- `YYYY-MM-DD 台股資金流入.txt`
- `YYYY-MM-DD 台股資金流出.txt`

不得等待融資融券資料。

### 第二階段：融資融券

通常約台北時間 21:00～22:00 後，當同日融資融券資料完整時，再獨立交付：

- `YYYY-MM-DD 台股融資融券觀察.txt`

若資料尚未公布，只標示第三份等待資料更新。不得使用前一交易日資料冒充，也不得覆蓋已完成的前兩份。

若系統具備排程或監控能力，應持續檢查指定交易日融資融券資料，完整後再交付第三份。

## 二、資料來源與完整性規則

### 法人資料

- 上市個股優先使用 TWSE 官方個股法人資料。
- 上櫃個股優先使用 TPEx 官方個股法人資料。
- 上市與上櫃資料必須轉成相同欄位後合併。
- 排除 ETF、ETN、權證及非普通股。
- 外資、投信、自營商分開處理，不得只交三大法人總額。
- 排名依買賣超張數排序；買超由大到小，賣超依絕對值由大到小。

### 日期規則

- 保存 `requested_date` 與 `resolved_date`。
- 指定日若為假日或官方尚未發布，才可回退最近交易日，且必須明確標示。
- HTTP 400、格式錯誤、連線失敗與真正查無資料必須分開處理。
- 不得把不同日期資料混在同一份報告。

### 融資融券資料

- 必須使用同一交易日實際融資、融券增減與餘額。
- 每檔至少保留：融資增減、融資餘額、融券增減、融券餘額。
- 不得沿用前一交易日數據。

## 三、台股資金流入固定格式

```text
YYYY/MM/DD 台股資金流入

大盤摘要：
加權指數收[收盤點數]點，[上漲/下跌][漲跌點數]點，漲幅[漲跌幅]%，成交值[成交值]億元。
上市三大法人合計[買超/賣超][金額]億元；外資[買超/賣超][金額]億元、投信[買超/賣超][金額]億元、自營商合計[買超/賣超][金額]億元。
盤面定性：[當日盤勢、主軸、追價或風險判斷]。

外資買超前十（排除ETF）：
[代號][名稱][張數]張、……共10檔。

投信買超前十（排除ETF）：
[代號][名稱][張數]張、……共10檔。

🟢卡片1｜[族群名稱]
代表股：[至少2至8檔]
籌碼：[具體法人買超數字與共振情況]
反人性：[價格與籌碼、內外資分歧或追價風險]
評分：[★☆☆☆☆至★★★★★]
操作建議👉[明確操作條件]
族群＆個股現象：[族群內部現象]
解讀：[資金意義]
延續性觀察：[隔日或後續確認條件]

🟢卡片2｜……
🟢卡片3｜……
🟢卡片4｜……
🟢卡片5｜……
```

### 資金流入硬性要求

- 外資買超前十完整10檔。
- 投信買超前十完整10檔。
- 固定5張綠卡。
- 每張綠卡固定八欄：代表股、籌碼、反人性、評分、操作建議、族群＆個股現象、解讀、延續性觀察。
- 卡片依資金強度、法人共振、族群一致性與延續性排序。

```text
外資賣超前十（排除ETF）：
[代號][名稱][張數]張、……共10檔。

評分：[★☆☆☆☆至★★★★★]

族群＆個股現象：[族群內部現象]
解讀：[資金撤出意義]
延續性觀察：[隔日或後續確認條件]

🔻卡片2｜……
🔻卡片3｜……
🔻卡片4｜……
🔻卡片5｜……
```

### 資金流出硬性要求

- 外資賣超前十完整10檔。
- 投信賣超前十完整10檔。
- 固定5張紅卡。
- 每張紅卡固定八欄：代表股、籌碼、反人性、評分、操作建議、族群＆個股現象、解讀、延續性觀察。
- 優先呈現法人集中調節、價格與籌碼背離、族群撤離與換股現象。

## 五、台股融資融券觀察固定格式

```text
YYYY/MM/DD 台股融資融券觀察

資料狀態：
[來源]融資增加、融資減少與融券增加排行已完整更新至[MM-DD]。
以下全部採用YYYY/MM/DD當日實際資券資料，不沿用前一交易日數據。

🟡卡片1｜[主題]
代表股：[至少3至8檔]
融資：[逐檔列出當日增減與最新餘額]
融券：[逐檔列出當日增減與最新餘額]
停券/回補：[資券結構判斷]
反人性：[追價、回補、多空分歧或槓桿風險]
評分：[★☆☆☆☆至★★★★★]
操作建議👉[明確條件]
延續性觀察：[隔日或後續確認條件]

🟡卡片2｜……
🟡卡片3｜……
🟡卡片4｜……
🟡卡片5｜……
```

### 融資融券硬性要求

- 固定5張黃卡。
- 每張黃卡固定八欄：代表股、融資、融券、停券/回補、反人性、評分、操作建議、延續性觀察。
- 每檔數字必須寫成「當日增減＋最新餘額」，例如 `+2,570至206,122張`。
- 必須分辨融資追價、融資減少、融券增加、融券回補、資券同步增加、資減券增與資券同步下降。
- 不得把融券增加直接等同一定軋空；必須搭配價格與成交量判斷。

## 六、聊天正文規則

主要交付物是三個 TXT，聊天正文只需簡短列出：

- 已完成：哪些檔案
- 等待中：哪些檔案及原因
- 實際採用交易日

不得把三份完整內容重複貼成長篇聊天文章，除非使用者明確要求直接展開內容。

## 七、資料不足時固定處理

若任一排行榜沒有取得完整同日資料：

1. 不得使用其他日期數字補入。
2. 不得只交法人總額冒充完整排行。
3. 明確回報缺少上市、上櫃、外資、投信、融資或融券哪一段。
4. 附上請求日期、解析日期、介面與錯誤類型。
5. 先嘗試上市／上櫃分流抓取、欄位正規化、合併與排序。
6. 仍失敗時才標示「當日完整排行尚未取得」。

## 八、禁止事項

- 禁止把「日期＋台股」改成簡短法人總額表。
- 禁止輸出自由發揮的盤後長文、夜盤分析或關鍵價位。
- 禁止把三份報告合併成一份。
- 禁止等待融資融券而延遲前兩份。
- 禁止少於前十名或少於五張卡片。
- 禁止省略卡片固定欄位。
- 禁止混用不同交易日資料。
- 禁止未取得資料卻自行補數字。
