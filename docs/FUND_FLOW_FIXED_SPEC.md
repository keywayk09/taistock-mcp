# 台股資金流入／流出／融資融券固定輸出規格

本檔是鑽石引擎與台股 GPT 的固定輸出契約。只要使用者要求「資金流入、資金流出、法人排行榜、融資融券」，必須先讀取本檔並完全依照此格式輸出，不得自行縮短、合併、改名或只交摘要。

## 一、固定交付檔案

每個交易日固定輸出三份 TXT：

1. `YYYY-MM-DD 台股資金流入.txt`
2. `YYYY-MM-DD 台股資金流出.txt`
3. `YYYY-MM-DD 台股融資融券觀察.txt`

日期必須是資料實際交易日。不得拿其他交易日資料冒充指定日期。

---

## 二、資料來源與排序規則

### 法人資料

- 上市個股：優先使用 TWSE 官方個股法人資料。
- 上櫃個股：優先使用 TPEx 官方個股法人資料。
- 上市與上櫃資料必須轉成相同欄位後合併。
- 排除 ETF、ETN、權證及非普通股標的。
- 外資、投信、自營商分開處理，不得只交三大法人總額。
- 排名一律依「買賣超張數」排序。
- 買超榜由大到小；賣超榜依賣超絕對值由大到小。
- 同一標的不得重複。

### 日期規則

- 保存 `requested_date` 與 `resolved_date`。
- 若指定日為假日或官方尚未發布，才可回退最近交易日。
- 若日期回退，檔案標題與正文必須明確寫出實際採用日期。
- HTTP 400、介面格式錯誤、連線失敗與真正查無資料必須分開處理。
- 不得把 HTTP 400 寫成「官方沒有資料」。

### 融資融券資料

- 必須使用同一交易日的實際融資、融券餘額與增減。
- 不得沿用前一交易日資料。
- 每檔至少保留：融資增減、融資餘額、融券增減、融券餘額。

## 三、資金流入固定格式

```text
YYYY/MM/DD 台股資金流入

大盤摘要：
加權指數收[收盤點數]點，[上漲/下跌][漲跌點數]點，漲幅[漲跌幅]%，成交值[成交值]億元。
上市三大法人合計[買超/賣超][金額]億元；外資[買超/賣超][金額]億元、投信[買超/賣超][金額]億元、自營商合計[買超/賣超][金額]億元。
盤面定性：[當日盤勢、主軸、追價或風險判斷]。

外資買超前十（排除ETF）：
[代號][名稱][張數]張、……共10檔。

投信買超前十（排除ETF）：
[代號][名稱][張數]張、……共10檔。

🟢卡片1｜[族群名稱]
代表股：[至少2至8檔]
籌碼：[具體法人買超數字與共振情況]
反人性：[價格與籌碼、內外資分歧或追價風險]
評分：[★☆☆☆☆至★★★★★]
操作建議👉[明確操作條件]
族群＆個股現象：[族群內部現象]
解讀：[資金意義]
延續性觀察：[隔日或後續確認條件]

🟢卡片2｜……
🟢卡片3｜……
🟢卡片4｜……
🟢卡片5｜……
```

### 資金流入硬性要求

- 外資買超前十必須完整10檔。
- 投信買超前十必須完整10檔。
- 固定5張綠卡，不得少於5張。
- 每張卡片八個欄位全部保留：代表股、籌碼、反人性、評分、操作建議、族群＆個股現象、解讀、延續性觀察。
- 卡片按資金強度、法人共振、族群一致性與延續性排序。

```text
族群＆個股現象：[族群內部現象]
解讀：[資金撤出意義]
延續性觀察：[隔日或後續確認條件]

🔻卡片2｜……

🔻卡片4｜……
🔻卡片5｜……
```

### 資金流出硬性要求

- 外資賣超前十必須完整10檔。
- 投信賣超前十必須完整10檔。
- 固定5張紅卡，不得少於5張。
- 每張卡片八個欄位全部保留。
- 優先呈現法人集中調節、價格與籌碼背離、族群資金撤離與換股現象。

## 五、融資融券固定格式

```text
YYYY/MM/DD 台股融資融券觀察

資料狀態：
[來源]融資增加、融資減少與融券增加排行已完整更新至[MM-DD]。
以下全部採用YYYY/MM/DD當日實際資券資料，不沿用前一交易日數據。

🟡卡片1｜[主題]
代表股：[至少3至8檔]
融資：[逐檔列出增減與餘額]
融券：[逐檔列出增減與餘額]
停券/回補：[資券結構判斷]
反人性：[追價、回補、多空分歧或槓桿風險]
評分：[★☆☆☆☆至★★★★★]
操作建議👉[明確條件]
延續性觀察：[隔日或後續確認條件]

🟡卡片2｜……
🟡卡片3｜……
🟡卡片4｜……
🟡卡片5｜……
```

### 融資融券硬性要求

- 固定5張黃卡，不得少於5張。
- 每張卡片必須包含：代表股、融資、融券、停券/回補、反人性、評分、操作建議、延續性觀察。
- 必須分辨：融資追價、融資減少、融券增加、融券回補、資券同步增加、資減券增、資券同步下降。
- 不得把「融券增加」直接等同必定軋空；必須搭配價格與成交量判斷。

---

## 六、資料不足時的固定處理

如果任一排行榜沒有取得完整同日資料：

1. 不得用其他日期數字補入。
2. 不得只交法人總額冒充個股排行。
3. 必須回報缺少的是上市、上櫃、外資、投信、融資或融券哪一段。
4. 必須附上實際請求日期、解析日期、官方介面與錯誤類型。
5. 先嘗試上市／上櫃分流抓取、欄位正規化、合併及排序。
6. 仍失敗時才標示「當日完整排行尚未取得」，不可生成假排行。

---

## 七、禁止事項

- 禁止只輸出摘要。
- 禁止少於前十名。
- 禁止把不同日期混在同一份檔案。
- 禁止省略卡片欄位。
- 禁止自行改成表格或短版，除非使用者明確要求。
- 禁止以網路搜尋結果取代已指定的官方同日排行。
- 禁止未取得資料卻自行補數字。

---

## 八、驗收清單

產出前逐項檢查：

- [ ] 交易日一致。
- [ ] 上市與上櫃皆已納入。
- [ ] ETF 已排除。
- [ ] 外資買超前十完整。
- [ ] 外資賣超前十完整。
- [ ] 投信買超前十完整。
- [ ] 投信賣超前十完整。
- [ ] 資金流入5張綠卡完整。
- [ ] 資金流出5張紅卡完整。
- [ ] 融資融券5張黃卡完整。
- [ ] 每張卡片固定欄位齊全。
- [ ] requested_date、resolved_date與來源可追溯。
- [ ] 沒有混用其他日期或臆造數字。
