# TRAI 交易研究 AI：研究基礎規格

## 專案定位

TRAI（Trading Research AI）不是單純的訊號產生器，而是一套持續復盤、累積案例、提出假說、驗證假說，再將成熟結論升級為正式交易引擎規則的研究系統。

台股引擎是 TRAI 的正式成果之一；Research、Knowledge、Decision Log、Data 與 Playbook 則構成其研究基礎。

## 核心目標

1. 每日從台股市場建立具代表性的研究樣本。
2. 使用個股與台指期分 K OHLCV 重建盤中價格路徑。
3. 評估現有指標標籤的品質，而不是只統計最後盈虧。
4. 找出漏訊號、錯誤訊號、過早、過晚、重複與不具交易價值的訊號。
5. 加入 AI／人工市場判斷，說明當下為什麼應多、應空或應觀望。
6. 累積 MFE、MAE、R 倍數、持有時間與不同出場結果。
7. 建立台指期趨勢線與線型案例資料庫。
8. 將研究結論轉為可驗證的修改假說，不因單一案例直接修改正式引擎。
9. 每次正式修改都保留完整決策依據與副作用評估。

## 固定研究流程

```text
市場資料
→ 建立樣本池
→ 取得 OHLCV
→ 重建價格路徑
→ 引擎訊號比對
→ AI 市場判斷
→ 分類 Verdict
→ 計算 MFE／MAE／R
→ 提出修改假說
→ 累積驗證
→ Decision Log
→ 經核准後進入正式 Engine
```

## 每日樣本池

個股樣本可由下列條件建立：

- 成交金額
- 成交量與量增
- 週轉率
- 振幅
- 漲跌幅
- 當沖活躍度
- 資金流向
- 特殊價格路徑
- 族群同步或背離
- 突破、假突破、回測、反轉、收斂等型態

樣本池只代表「值得研究」，不等於隔日推薦。

## 引擎對照範圍

每日復盤至少檢查：

- S1、S2、S3、S5
- L1、L2
- RBND
- BRK／TRND
- SQCH／LSQ
- Raw → Seed → Commit → Distance → RR → Entry → 正式標籤

## Verdict 分類

- `CORRECT`：訊號與當下市場結構合理。
- `MISSED`：具交易價值的機會未出現訊號。
- `WRONG`：不應交易卻出現訊號。
- `REASONABLE_NO_TRADE`：事後有行情，但當下不具充分交易條件。
- `NEED_MORE_DATA`：資料不足，不應下結論。

## 標籤品質

每個標籤至少評估：

- 位置
- 市場背景
- 價格結構
- 量價品質
- 價格承諾
- 距離
- 風報比
- 時機
- 去重與事件狀態

品質可分為：

- A：漂亮、結構完整、具明確交易價值
- B：方向與結構合理，但存在次要缺點
- C：普通、邊際不足，應持續觀察
- D：不漂亮，通常不應出現正式標籤

## 問題分類

研究結論必須區分：

1. 資料問題
2. 程式實作問題
3. 策略定義問題
4. 參數過嚴或過鬆
5. 市場背景否決缺失
6. 合理不交易
7. 樣本不足

## 修改假說

每個假說至少包含：

- 假說編號
- 涉及策略
- 問題描述
- 支持案例數
- 反例數
- 預期改善
- 可能副作用
- 信心等級
- 尚需樣本數
- 是否建議進入實驗

單一漂亮案例不得直接進入正式 Engine。

## 台指期與趨勢線研究

台指期同時具有兩個用途：

1. 作為個股訊號的市場背景。
2. 建立獨立的趨勢線與線型研究資料庫。

趨勢線資料至少記錄：

- 合約、日盤／夜盤、時間週期
- 起點與終點時間／價格
- Pivot 選擇
- 斜率
- 觸碰次數
- ATR 或點數容許誤差
- 突破時間
- 是否收盤確認
- 是否回測
- 假突破與否
- 突破後 MFE／MAE
- AI 判斷
- 引擎判斷
- Verdict

線型至少分類為：

- 上升趨勢線
- 下降趨勢線
- 平行通道
- 水平支撐／壓力
- 收斂三角
- 擴散
- 旗形
- 楔形
- 斜率轉換

趨勢線資料先研究與驗證，樣本足夠後才轉為正式指標規格。

## 智能化的定義

TRAI 的「智能」不是增加更多指標條件，而是讓系統逐步具備：

- 辨識市場背景
- 理解事件進度
- 判斷條件是否已失效
- 知道何時應等待
- 評估位置與風報比
- 避免同一事件重複出標
- 針對趨勢盤、區間盤與反轉盤採用不同判斷

## 正式引擎修改門檻

任何修改進入正式 Engine 前，必須具備：

- 可追溯案例
- 足夠樣本
- 修改前後比較
- 高品質訊號保留率
- 錯誤訊號降低幅度
- 新增錯誤與漏訊號副作用
- 不同市場狀態驗證
- Decision Log
- 使用者核准
